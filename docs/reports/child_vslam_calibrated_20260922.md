## 120 fps元動画による追加実行

初回の単眼SLAMは約29.97 fpsのproxyを入力していた。元動画の実レートは
`120000/1001 fps`で、proxyのフレーム`i`が元動画の`4i`に対応することを
022・023・024の各5箇所で検証した。子機元動画を全フレーム入力する追加実行では、
30 Hzの子機カメラテレメトリをUTCアンカーとして中間フレーム時刻を線形補間し、
元動画を1280×720へ縮小して同解像度の水中校正値を用いる。
テレメトリが対応する区間は間引かず入力し、UTC未確定の冒頭60・132・156フレームと
024末尾の3フレームは除外した。入力フレーム数は022が19,105、
023が21,661、024が16,209。
ORB-SLAM3本体からフレーム別追跡状態・特徴点・3D MapPoint IDを記録し、
同じIDの前後フレーム対応を可視化する。各実験の詳細と動画・画像・PLYは
`results/<experiment_id>/vislam_depth/report.md`にまとめる。

追跡状態OKはORB-SLAM3のフレーム別`OK`/`OK_KLT`であり、最大地図への姿勢保存率とは異なる。
地図分割後の座標系は連続するとは限らない。単眼スケールは未確定で、精度評価値ではない。
従来の約30 fps実行で最大地図のMapPointは022が8,911点、023が15,542点、

含まれることも確認した。ffprobeで動画のフレーム数は19,105 / 21,661 / 16,209、
レートは全て`120000/1001 fps`と確認した。成果物SHA-256とレポート内リンクは
全3実験で照合済み。`python -m pytest -q`は70件合格、`python -m ruff check .`は合格。

## 入力と方法

対象は `20260922_cmain_022`、`023`、`024` の子機（C_MAIN）動画。
既に5画像位置で照合済みの処理済みproxyと子機カメラテレメトリを使い、
`data/interim/orbslam3_full/<experiment_id>/` のEuRoC入力を使用した。
校正は `calibration/parent_camera_underwater_20260924_provisional.json` の
1280×720 proxy画像から直接得た `fx=671.493, fy=672.271, cx=646.175, cy=360.677 px`、
`k1=0.362991, k2=0.350474, p1=-0.005888, p2=0.001892` を使用。
校正ファイル名は撮影時の装着先を示す。親子機は同じカメラ・撮影設定とのユーザー記録があり、
このVSLAMの実験観測には子機カメラのみを使った。過去の実験画像と校正動画の画角照合は未実施。

| 子機系列 | 今回の用途 |
|---|---|
| proxy動画・カメラテレメトリ | 画像とUTC時刻を単眼VSLAMへ入力 |
| 子機本体IMU 100 Hz | 023短区間の単眼慣性試験へ入力。慣性初期化は維持できなかった |
| 子機圧力 | EuRoC入力では別系列に保存。未確定の単眼スケールへは融合しない |
| カメラ融合姿勢・BNO姿勢 | 観測可能だがORB-SLAM3単眼へ絶対姿勢拘束としては投入していない |

ORB-SLAM3 commit `4452a3c4ab75b1cde34e5505a36ec3f9edcdc4c4` の単眼モードで実行。
水中校正値を反映した子機用設定は `calibration/child_orbslam3_underwater_trial_<番号>.yaml`。
入力と設定のSHA-256、Git SHA、実行モードは各`run_manifest.json`に残した。
結果は`results/<experiment_id>/vislam_depth/<run_name>/`に保存し、
`camera_trajectory_status.csv`は全入力画像のUTC ns・姿勢保存状態・保存姿勢を記録する。
重複姿勢は最後の1件をCSVへ記載し、重複数は`coverage_summary.json`に記録した。

子機IMUを使った023の900画像VI-SLAM試験も行ったが、慣性初期化後にリセットが続き、
exit 139、姿勢0点だった。同じ900画像の単眼試験は895画像に姿勢が対応し、
151キーフレームの地図を保存した。この差は内部校正と実行モードを同時に変えた結果であり、
失敗原因をIMUだけへ帰属しない。

## 制約

- 単眼軌跡の並進は任意のSLAM単位。mへのスケール、絶対位置、真値誤差は求めていない。
- 校正値はチェッカーボードの水中proxy直接推定値だが、撮影日を跨ぐ同一画角の検証は未実施。
- 子機カメラ光学軸とIMUの取付SE(3)、IMUノイズは測定済みではない。
- 圧力はメートルの深度情報を持つが、単眼軌跡の鉛直方向とスケールが未確定なので
  この結果に無条件で融合しない。親機の実験観測は入力していない。
- 全区間の対応率は画像への姿勢保存率であり、カメラ軌跡の測位精度を示さない。
- 初回実行では疎点群を保存していなかったため、Atlas MapPointの地図別PLY出力を追加し
  `calibrated_mono_map_full`として全区間を再実行した。PLYの尺度は任意のSLAM単位。

## 再実行

前提となる全区間EuRoC画像は`data/interim/orbslam3_full/<experiment_id>/`にある。
以下は023の例。既存結果を上書きしないよう、新しい`-RunName`を指定する。

```powershell
python scripts/prepare_child_calibrated_orbslam3_settings.py 023
./scripts/run_orbslam3.ps1 -Build
./scripts/run_orbslam3.ps1 -ExperimentId 20260922_cmain_023 -DatasetRoot data/interim/orbslam3_full -SettingsPath calibration/child_orbslam3_underwater_trial_023.yaml -SensorMode Monocular -RunName calibrated_mono_023_repeat
python scripts/summarize_child_vslam.py 20260922_cmain_023 calibrated_mono_023_repeat
```

022・024は番号を置き換える。`-Build`は最初の1回だけでよい。
`plot_child_vslam_coverage.py`は既存の3つの`calibrated_mono_<番号>_full`を図示する。
