# Nanyo：別PCへの引き継ぎ（2026-11-02）

## 最初に行うこと

```powershell
git clone https://github.com/AquaBeacon/aquabeacon-analysis.git
cd aquabeacon-analysis
python -m venv .venv
.venv\Scripts\python -m pip install -e ".[analysis,media,vision,mapping,replay,dev]"
```

旧PCの `data/processed/` を、新PCのこのリポジトリの `data/processed/` へ同じ構造でコピーする。
移行確認が通るまで旧PCのデータを残す。動画もCSVも改名しない。

```powershell
.venv\Scripts\python scripts/verify_nanyo_handoff.py --experiment 20261101_nanyo_000 --verify-csv
```

この確認はraw/interimや旧PCの絶対パスを必要としない。転送したファイルの存在・サイズ、
155個の区間CSVの行数・UTC境界・区間秒を確認する。サイズ確認は暗号学的ハッシュ検証ではない。
day1も移した場合は `--experiment 20261031_nanyo_000` で確認できる。

親機0193/0194/0195と0197、子機0028/0029と0030は再起動前後で別セッション。
全7動画を独立同期し、最後の実験005には0197/0030の時計を使う。
同期係数は `results/20261101_nanyo_000/synchronization/manifest.json` にある。
自動分割の継ぎ目、004/005の子機末尾などの外挿フラグを保持する。

解析の入力は各実験の `data/processed/<id>/synchronized/`。
`sync_utc_s` が共通UTC、`segment_time_s` が区間内の秒。元の単調時計を親子間で直接比較しない。
親機shotの `parent_scheduled_us` は親機時計、`tx_us` は子機時計。
動画は各区間の `videos/parent.mp4` と `child.mp4`、秒数対応は `*.clock.json` を参照する。
`*_concat_untrimmed.mp4` はタイミング補正前のバックアップで、解析には使わない。転送は任意。
`parent_part*.mp4` / `child_part*.mp4` は無再圧縮の部分動画として保持する。
MP4のcreation_timeはplaceholderであり計測時刻ではない。

最終検証：親子動画10本、24箇所の復号フレーム一致、155 CSV・5,855,263行の境界と件数。

## GitHubに含むものと手元に残すもの

- GitHub：Nanyoのコード、テスト、設定、実験台帳、文書、結果のJSON（点群sceneを除く）・解析CSV・レポート、同期／区間の診断グラフ。
- 手動転送：`data/processed/`。Nanyo day1/day2の対象一覧は [nanyo_processed_inventory.json](nanyo_processed_inventory.json)。
- GitHubに含めない：raw、interim、動画、抽出画像、点群／メッシュ、COLMAP workspace、pickle、ローカル認証情報。
- raw/interimは今回のday2区間CSVから次の解析を始めるだけなら不要。原本から再同期・再切出し・元フレーム照合をやり直す場合には必要。
- day1の既存航法／地図を再実行する場合、コードがinterimのgeometry・磁気ログ・画像等を参照する。必要に応じて `data/interim/20261031_nanyo_000/` と区間001/002を別途転送するかrawから再生成する。
- 既存3D viewer、写真素材、地図scene、編集用pickle等は今回のGit配布対象外。レポート内の未配布ファイルへのリンクは、新PCで再生成または追加転送するまで開けない。

manifestや動画sidecarの旧PC絶対パスは当時の来歴として保持した。`data/processed/` 以降を
新PCのリポジトリ直下へ読み替える。ハッシュを変えるため過去manifestを一括置換しない。
通常の同期・分割検証スクリプトは原本／interimと旧パスを参照するため、移行直後は上記の専用確認コマンドを使う。

## 再処理と次の担当者への注意

再処理のコマンドはREADMEとAGENTSのNanyo day2節にある。
子機BNO kind16の再デコードには対応するfirmware checkoutを `--firmware-root` で明示する。
この解析リポジトリはfirmwareの配布を兼ねない。旧実行時のreader hashはdecodeの来歴に記録済み。
day1の絶対位置・航法系スクリプトには `ACQ = "20261031_nanyo_000"` という固定対象がある。
day2にそのまま流用せず、対象ID、ログsuffix、カメラセッション、取付校正の適用条件を見直す。
別日の時計・取付校正・固定区間一覧を暗黙に流用しない。同期残差を絶対精度とは呼ばない。

作業時点の全体テストは262件通過、既存のPNG-only出力チェック1件失敗。
`anchor_nanyo_maps.py` 等の3D出力の `savefig` が現在の一律チェックに抵触する。
今回の同期・分割の関連35テスト、CSV／動画検証は通過している。
これは位置推定等の全処理の再実行成功を意味しない。

今回の移行確認を現PCで実行し、day2の204ファイル、155 CSV・5,855,263行で合格。移行確認の2テストを含む関連37テスト、追加コードのRuff、ワークスペース構成検証も合格。Nanyoの転送対象はday2約59.48 GB、day1約37.73 GB（補正前concatバックアップ・ログを除く）。
