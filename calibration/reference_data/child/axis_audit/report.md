# 子機の軸校正と再利用（2026-10-29）

追加された29567のIMU・BNOイベント・HEALTHログを照合し、BNO085センサ軸から機体FRD（前・右・下）への固定回転を保存した。
校正用21,462行、本番20261028_ngt_000の157,855行に適用した機体姿勢を別フォルダへ出力した。原本・既存の融合結果は変更していない。

## 校正値と使い方

校正：`calibration/20261029_child_axis_003_imu_frd.json`。
台帳のcalibration_pathsに明示参照する。台帳への登録だけでは既存解析の値を自動変更しない。
新規の同一取付構成へ使う場合も対象を明示する。別機体、BNOの取り外し・付け直し、機体前方向の定義変更時は再校正する。
本番への適用は同じ実機配置というユーザー確認に基づき、取付再現性の独立測定はない。

`v_body = R_body_from_sensor @ v_sensor`

姿勢は `R_world_from_body = R_world_from_sensor @ R_body_from_sensor.T`。
出力はw,x,y,zの四元数。BNOゲーム世界のyawは任意であり、磁北・ENU方位ではない。
カメラと水中ライトの固定位置はCADと逆という確認を `child_mount_20261028_actual.json` に記録。
固定位置の交換から回転180度や正確な測定中心を推測していない。

```powershell
python scripts/audit_child_axis_calibration.py --experiment 20261029_child_axis_003 --firmware-root ../firmware-experiments
python scripts/calibrate_child_axes.py --experiment 20261029_child_axis_003 --firmware-root ../firmware-experiments --target-experiment 20261028_ngt_000
```

上記は明示した今回の4姿勢設定から再生成する。将来の別校正には独立台帳と設定を登録する。
Python API `body_quaternions(q, R)` は保存回転を適用できる。qはsensor→world、回転はsensor→body。

## 4姿勢の検証

機体ID A521D21EB1DCFB44、boot 1749629566、個別校正番号2を参照。
全入力をCRC付きreaderで読み、マーカーとIMU/BNO/HEALTHのsession一致を確認。
水平・機首上・右側上・機尾上の4区間を用いる。区間の冒頭1秒と末尾0.25秒は静止待ちとして明示的に除き、除外前の区間全体でもIMU時刻と連番を点検した。

| 姿勢 | 新規加速度点数 | 方向残差 |
|---|---:|---:|
| 水平 | 1037 | 約0°（基準として使用） |
| 機首上 | 775 | 2.612° |
| 右側上 | 627 | 1.549° |
| 機尾上 | 897 | 2.145° |

静止性・加速度ノルム・分散を既存手順と同じゲートで確認し、方向残差5°以内を通過。
これは姿勢の幾何整合性であり、絶対精度や真値誤差ではない。
BNO四元数で各姿勢の加速度を世界へ回すと、全4姿勢で約+Zへ一致し、sensor→worldの向きも確認した。

姿勢4ではマーカーdropが276増加。HEALTHのdroppedも0→276、imu_gapsは263で不変、リセット0。
**100Hz IMUの全姿勢区間には連番飛びがなく、最大時刻差は約11.3ms。**
複数ストリームの総合dropをIMU欠測と同一視せず、今回の姿勢算出用IMUに欠損がないことを直接確認して採用した。
他ストリームの欠落は回復していない。記録は `health_review.json` とsolutionのpose_windowsに保持。

開始event7・完了mask15は手元の旧firmware解析器の想定外。
今回は既存手順の4姿勢ラベルと観測された区間開始・終了を明示設定してオフライン解析した。
旧readerでCRC検査は可能だが、firmwareの軸プロファイルとして検証したものではなく、SDインポート用とはしない。

## カメラの検証と採用範囲

DJI_20261029223001_0187_DのLRFから5,516行を抽出。映像60秒地点は室内天井・壁の画角で、実機の取り付け位置そのものは確認できない。
カメラ角速度の大きさと子機ジャイロを、子機の単調時刻を基準に照合。

| 動画区間 | 時刻差候補（子機秒−動画秒） | 相関 |
|---|---:|---:|
| 10〜60秒 | 455.776秒 | 0.980 |
| 60〜110秒 | 455.784秒 | 0.999 |
| 110〜138秒 | 455.760秒 | 0.713 |

後半で不一致があるため、全動画用の時刻変換・カメラIMU→機体回転は未採用。相関の良い区間だけで全区間合格とはしない。
本番動画へ今回の時刻差を転用しない。カメラの未採用は、独立した4静止姿勢によるBNO軸変換の算出を妨げない。

## 出力と検証

- 校正値・入力/config/reader/生成コードのSHA256・Git SHA：`solution.json` と校正JSON。
- 入力監査：`manifest.json`。数値校正の成否はsolutionを参照。
- 校正収録の機体姿勢：`../child_body_attitude/attitude.csv`。
- 本番の機体姿勢：`results/20261028_ngt_000/child_body_attitude/attitude.csv` と同フォルダのmanifest/report。
- CSVは原本の時刻・fresh_maskを保持。更新のない値も保持し、`fresh_mask & 1` で新規四元数を選べる。欠損を補間しない。
- 元のカメラ融合結果とは別のBNO機体姿勢。磁気校正・地理方位・レバーアームの校正は含めない。

合成既知回転の復元、四元数の変換方向、誤姿勢・ギャップ・不正回転の拒否を自動テスト。

最終検証：自動テスト168件成功、全体ruff成功、diff空白検査成功。実データ再生成成功、全入力SHA256再照合、校正参照SHA256と出力四元数の単位ノルム・行数を確認。作業用常駐プロセスなし。
