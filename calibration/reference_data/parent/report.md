# 親機の軸校正011・時刻合わせ・校正部分の切り出し

## 結果

4静止姿勢のSpresense→機体FRD（前・右・下）回転と、カメラ内IMU→機体回転を検証して保存した。
磁気センサの機体軸合わせは姿勢間整合性基準を満たさず不採用。絶対方位は確定していない。
原本は変更せず、今回の結果を独立した実験ID `20261029_parent_axis_011` に保存した。

[校正区間の動画](calibration_only.mp4) ／ [機体姿勢CSV](body_attitude.csv)

## 入力の対応

- 親機 `P_MAIN_BODY_CAPTURE_00011.bin`、機体A444A41EE9334705、boot2323944385、IMU校正3・磁気校正1。
- マーカー参照先は `P_MAIN_TIME_POSITION_44386.bin` / `P_MAIN_HEALTH_RANGE_44386.bin`。採用磁気はHEALTH内kind10の補正済み値。
- 対応するSpresenseは **I00013.BIN / T00013.BIN**。ログ番号ではなくparent_sessionを照合。
- I00013全2,097,120サンプルをCRC検証、保存seq連続性を確認。校正区間の90,863サンプルを保持。
- 最初に親機DJIへ置かれていた0187は子機動画とハッシュ一致していたため不採用。ユーザー差し替え後の **DJI_20261029225449_0025_D.MP4/LRF** を使用。
- 子機のカメラ／ライト位置交換という情報は親機へ転用していない。親機と子機は別の校正値・時計・座標を持つ。

## 時計の対応

今回のSpresenseにGNSS同期UTCはなく、校正区間はtime_quality=1。
RTC→端末時計の切替もあるため、参考UTCの単純な差引きや子機時計の流用はしない。
T00013の親機由来端末時刻をHEALTHの同じUTCアンカーで逆変換し、43個の対応点から機器間の単調時計差をフィットした。

`parent_mono_s = spresense_mono_s + 1.099824814 + 0.00001875120631 * (spresense_mono_s - 2101.161870209)`

対応点の最大残差0.594ms。これは内部の対応整合性であり、パケット受信遅延や絶対UTC精度の保証ではない。
冒頭のRTC区間へは同一起動内のこの式を外挿している。静止姿勢は冒頭1秒・末尾0.25秒を除いて評価。
親機のマーカーsample_sequenceはキャッシュされたサンプル数なので、最新IMUと同時刻のサンプル番号とは見なさない。

カメラとの対応は姿勢変更の角速度ノルムから求めた。

`parent_mono_s = source_video_s + 1954.260`

| 元動画の動作区間 | 時刻差 | 相関 |
|---|---:|---:|
| 75〜88秒 | 1954.258秒 | 0.99850 |
| 97〜106秒 | 1954.260秒 | 0.99912 |
| 114〜131秒 | 1954.264秒 | 0.99883 |

時刻差は中央値を採用。カメラ時計の倍率は1に固定し、短い区間でドリフトを検証したとはしない。
すべてBODY_CAPTURE開始〜完了の内部。子機の時刻差を転用していない。

## 切り出し

元動画 **46.700643〜140.720810秒**、親機単調時刻2000.960643〜2094.980810秒。
1080p・120000/1001fps（約119.88fps）を保持してH264 CRF18で再エンコード。出力94.042秒。
コンテナの長さにはフレーム・音声サンプル単位の丸めを含む。

- imu.csv：Spresense原本の生値・補正値・時計・品質を保持、parent_mono_s/source_video_s/clip_time_sを追記。
- camera.csv：2,818行、元LRFテレメトリと共通の時刻を保持。再生成動画のテレメトリを原本の代用にしない。
- magnetic.csv / health.csv：親機時計で同じ区間を抽出。
- pose_1_imu.csv〜pose_4_imu.csv：4姿勢のマーカー区間。
- body_attitude.csv：カメラ世界に対する機体FRD姿勢（w,x,y,z）。カメラ世界のyawは任意、絶対方位ではない。

加速度ノルム・静止性・分散・方向残差5°ゲートを通過。最大サンプル間隔約1.133ms。
方向残差は4姿勢の幾何整合性であり、真値誤差ではない。
カメラ取付回転は75〜108秒で推定、114〜131秒で独立検証：256点、相関0.99822、RMS角速度差0.02934rad/s。

`R_body_from_camera_imu = R_body_from_spresense @ R_camera_imu_from_spresense.T`

`R_world_from_body = R_world_from_camera_imu @ R_body_from_camera_imu.T`

校正値：`calibration/20261029_parent_axis_011_axes.json`。同じ機体・取付け・前方向定義の場合に明示選択して再利用する。
本番の既存解析の一括再生成はしていない。校正用動画の時計変換を本番クリップへ流用しない。
カメラ内IMUの回転であって光学座標・内部標定・測定中心・並進の校正ではない。
開始event7/mask15は今回も4姿勢のオフライン解析として扱い、firmwareインポート形式ではない。

## 磁気方位の検証

親機の磁気センサとSpresenseは別センサなので、IMU軸変換をそのまま磁気へ使わない。
補正済み磁気の4姿勢平均から、独立した磁気センサ→FRD回転を既存firmware解析器で検証。
磁場ノルム平均は52.92 / 58.64 / 58.61 / 53.83µT。
ノルム条件だけでは合格とせず、姿勢1〜3の磁場方向の一致と姿勢4を含む検証も要求したが、5%整合性ゲートで不合格となった。

`R_body_from_mag=null`、`absolute_heading_valid=false`。
磁気校正を実施していないという意味ではなく、保存済み校正を使った今回の観測が機体軸合わせの整合性を満たさないという判定。
磁場変動・取付け・姿勢の方位保持のどれが原因かは確定しない。磁北や真北を無理に補完しない。
